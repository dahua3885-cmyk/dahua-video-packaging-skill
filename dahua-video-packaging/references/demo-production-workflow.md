# 生产流程

## 1. 冻结输入

- 用用户点名的最新版 MP4 作为人物与音频唯一真源。
- 用 `ffprobe` 记录路径、时长、分辨率、帧率、视频轨、音轨和修改时间。
- 抽取主音轨并记录 MD5；用户只说“包装”或“剪辑已经做好”时，默认口播与音频 `0 刀`，不剪切、不重排、不变速、不调色。
- 用户提供对标并说“按这个效果”时，从对标抽取至少 `10` 张代表帧，实测页面构图、开头结构、镜头节奏和素材关系；禁止凭印象估值。“按这个效果”不自动覆盖人物、字幕和黄框固定层。
- 收集真实网站、Markdown、操作界面、报告、数据页和结果页；优先使用用户自己的页面和可验证真源。
- 用户说“剪辑做好了”时，不改口播顺序、颜色、速度和音频。
- 建立冻结表，记录已确认的人物、字幕、页面区间、黄框、结尾和封面底版。
- 用户要求“在前面某版基础上改”时，把该版工程、视觉基调、信息架构和认可模块登记为唯一基准；未经点名的层全部冻结。
- 原片自带封面时，逐帧记录封面结束帧、正文第一帧和第一字音频；封面只全屏使用一次，人物、字幕、音频与语义时间轴一起平移。
- 局部返修只改点名层与点名区间；禁止为去边框、改字幕或改黄框重建其他已确认层。
- 先判断内容是“真实界面举证”还是“多种包装比较”。用户要同一条内容展示两种以上效果、把旧成片放在左侧讲解、或横屏测试三种包装时，选择 `packaging-comparison` 并读取 [demo-landscape-comparison-mode.md](demo-landscape-comparison-mode.md)。

## 2. 先判断画幅

- 宽桌面网页、数据表、多栏报告：优先 `1920×1080` 横屏。
- 单列手机页面、人物仍是主角：才考虑 `1080×1920` 竖屏。
- 不用局部无限放大补救错误画幅。首轮就用三张关键页测试可读性。
- 横竖屏测试、版式 A/B 测试和标题测试都新建递增版本；不得覆盖用户要保留的上一版。
- 横屏项目在制作前运行 `python -X utf8 "<本 Skill 目录>/scripts/fixed_layout_contract.py" init "<工程目录>"`，生成项目 `layout_contract.json`；再将 [demo-fixed-layout-contract.md](demo-fixed-layout-contract.md) 的语义规则写入项目 `reference_contract.md`。人物、字幕和黄框不得留成“后面再调”的开放项。
- 竖屏项目在制作前运行 `python -X utf8 "<本 Skill 目录>/scripts/fixed_layout_contract.py" init "<工程目录>" --mode vertical`，并执行 [demo-vertical-layout-contract.md](demo-vertical-layout-contract.md)。人物、字幕、主证据区、原片封面和发布分辨率不得留成开放项。
- 用户明确指定新对标时，将创意项实测值写入项目合同并冻结；只有用户明确点名的人物／字幕／黄框项目才允许覆盖，未点名的固定项继续沿用默认合同。

## 3. 建立语义真源

- 从音频抽取逐词时间轴，保留逐字时间戳。
- 首轮转写后专项回听否定词、数量、容量、百分比、产品名、英文名、技术名词和结果数字；同时对照真实页面文字。
- 未听清的词必须标记并回听，不得用旧字幕、页面内容或常识猜测。
- 按“操作 / 证据 / 结论 / 转场”划分语义场景。
- 为每个场景填写 [demo-semantic-timeline-template.md](demo-semantic-timeline-template.md)。
- 对账号主页、作品墙、具体案例原视频和旧成片分别登记证据类型，禁止用一个近似截图替代不同语义对象。
- 明确标记 `introEnd`、每个 `caseStart/caseEnd` 和 `conclusionStart`；案例画面不得越过自己的语义边界。
- 页面与口播不匹配时，先换页面或调整场景边界，不用装饰掩盖。
- 没有对应证据时允许保持稳定背景，不得拿无关页面凑画面。

## 4. 准备页面镜头

- 为每个辅助录屏记录安全时间段，检查开头 `2s`、结尾 `2s` 与全片 `1fps` 抽帧，排除 OBS、录屏控制栏、错误窗口和隐私画面。
- 真实操作需要被理解时，录制点击、分享、复制、输入、生成或切页。
- 结果解释优先使用预先裁好的独立静态镜头；每个镜头只承载一个阅读重点。
- 当前口播描述多个状态时，准备对应的多个真实状态；不能用一张图贯穿“开始—失败—结果”。
- 长网页先确定滚动起点、终点、方向和口播触发字，再录制或编排。
- 真实过程太慢时加速原录屏；不得用静态截图组替代扫描、滚动、框选和结果变化。
- 评论、点赞、统计、表格必须保留真实来源；无水印外部素材需记录来源和许可。
- 所有网络素材在渲染前下载到本地，渲染期间不依赖网络。

## 5. 组合三层画面

- 主层：真实页面或操作，占最大画面。
- 讲解层：横屏固定 `210×352, x=1676, y=690`，只保留圆角，不加描边和蒙层。
- 阅读层：固定 `44px` 白色粗体、底部居中短黑胶囊，跨场景不跳位。
- 滤镜顺序固定为：页面及页面标注完成后叠人物，最后烧录字幕。人物之后不得再加全屏效果或全局调色。
- 页面重点与固定层冲突时，调整页面裁切和位置；不得移动人物或字幕。
- 页面风格来自真实产品；外围包装保持克制，不用额外标题栏长期占宽度。
- 横屏比较模式改为“左侧真实动态样板 + 右侧解释文字 + 右下固定讲解人物 + 底部字幕”；样板和讲解人物是两个不同角色，不得互相替代或混成一个小窗。

## 6. 动作编排

- 语义场景变化：直接切换或短交叉叠化。
- 当前重点：页面停稳后再按固定合同画细黄框；其他标注形式只有用户明确要求时才使用。
- 长页阅读：只在需要浏览连续内容时滚动。
- 点击、鼠标、分享面板等动作必须对应口播中的真实操作。
- 动作结束后留出阅读时间；不能刚看清就切走。

## 7. 内部预检

- 首轮只渲染“开头 3 秒 + 一个完整案例／包装讲解段”作为内部门槛样片；不得直接先跑完整片。
- “一个完整案例”固定指从问题被首次说出，到过程／证据展开，再到结果被明确说出的完整闭环；优先选择片中第一个同时具备“问题—过程—结果”的案例，不得只截一个结果镜头代替。
- 将门槛样片与对标代表帧做并排对照，逐项核对人物尺寸和坐标、字幕样式和基线、黄框线宽和遮挡、页面可读性。
- 按当前画幅运行 `python -X utf8 "<本 Skill 目录>/scripts/fixed_layout_contract.py" validate "<工程目录>" --mode <landscape|vertical>`；固定参数必须完全一致。未通过时修正模板层，不得用局部补丁掩盖。
- 抽帧检查开头、第一段操作、画幅／缩放切换点、数据或评论段、结尾。
- 检查开头在案例关键词前没有提前进入案例；检查最后一个案例结束后不再出现任何案例录屏。
- 检查每个证据是否从对应对象第一次被说出的播放帧进入，且没有晚到后半句；允许的上下文预置不得早于约 `0.2s`。
- 检查同一证据跨字幕切句时是否复用同一容器；所有切换点前后各抽 `3` 帧，排除重影、重复叠层和跳动。
- 滚动段同时检查开始帧、中间帧、结束帧和连续播放。
- 逐句核对口播、字幕、页面、标注四者是否一致。
- 发现内容错、画面错、时机错、运动错或构图错时，按问题层级修正，不追加表面补丁。
- `fixed_layout_contract.py` 只校验机器可读的固定像素合同；逐句语义、遮挡和时机必须按本节人工抽帧与连续播放检查，不得把脚本通过当作整片通过。

## 8. 渲染和交付

- 预览通过后从完整工程高质量重渲，不能把低清样片放大成交付版。
- 需要时将原片音轨以 stream copy 重新挂回成片，避免音频二次压缩。
- 所有被用作整片底图、中间母版或长时覆盖层的资产必须先用 `ffprobe` 确认有效时长覆盖完整正片；禁止依赖末帧冻结补足。
- 局部返修必须以最近一次完整、已确认、时长正确的预览为底，不得退回更早或更短的中间母版。
- 用 `ffprobe` 和整文件解码检查编码、分辨率、帧率、音轨、时长和可播放性。
- 从最终 MP4 每 `1–2s` 抽帧扫描一次，并在 `25% / 50% / 75% / 95%` 时点确认背景仍在正常更新；整文件能解码不等于内容正确。
- 连续播放所有扫描、滚动、点击、框选和切页段，确认没有被静态化、反向或错误加速。
- 核对主音频校验值；无封面包装版应与源音频一致，带封面版应在去除封面静音段后保持原正片音频与首字完整。
- 用户要求发布封面时按 [demo-cover-contract.md](demo-cover-contract.md) 制作，并逐帧确认封面与原正片边界。
- 从最终 MP4 再抽取所有修改时点确认改动已进入交付文件。
- 未确认版本留在工程目录；用户明确确认后再复制到用户指定的成片目录。
- 交付时提供可点击的最终文件路径，并明确说明是否剪切口播、封面占几帧和最终时长。
