## 1. 真源和冲突处理

### 1.1 文件职责

- `source.mp4`：人物和音频唯一真源。
- `captions.json`：字幕内容、时间、重点词和双位置唯一真源。
- `production-timeline.json`：卡片、子事件、语音 cue、布局测量和状态交接唯一真源。
- `assets/fullframe-contract.css`：坐标、字号、颜色、间距和组件样式的可执行数值真源。
- `assets/fullframe-motion-tokens.js`：动画时长、位移和缓动的可执行数值真源。
- 本文件：上述数据如何建立和使用的行为合同。

HTML、GSAP、故事板和验收清单必须从这些真源生成或核对，不得独立手写第二份参数。

### 1.2 冲突处理

- 用户对当前成片的新反馈优先于现有合同；确认是跨片规则后，先修改共享真源再返修本片。
- 行为问题以本合同为准，视觉语义以 `fullframe-visual-standard.md` 为准，精确数值以两个 `assets/` 文件为准。
- 文档描述与资产数值不一致时视为硬错误：停止渲染、同步两者并重新校验，禁止任选一个继续。
- 历史工程、旧 `style-spec.md` 和旧 CSS 只作参考，不得覆盖当前真源。

## 2. 布局和视觉令牌

画布为 `1080×1920`。直接复制 `assets/fullframe-contract.css`，不得重新声明以下变量：

| CSS 变量 | 约束 |
| --- | --- |
| `--dahua-caption-top-plain` | 无卡片字幕固定上方位置 |
| `--dahua-caption-top-with-card` | 有卡片字幕固定下方位置 |
| `--dahua-card-bottom` | 卡片统一底边 |
| `--dahua-caption-card-gap` | 卡片底边到有卡片字幕顶边的固定间距 |
| `--dahua-card-min-height` / `--dahua-card-max-height` | 卡片内容自适应范围 |
| `--dahua-card-stack-gap` | 分阶段卡最终纵向组的默认间距 |
| 字幕、颜色、圆角和节点变量 | 跨期统一视觉身份 |

固定约束：

- 全片只使用同一字幕字体、字号、底板、关键词样式和动画；只允许在 `plain` 与 `with-card` 两个位置间按条切换。
- 无卡片字幕上移到卡片内容区；有卡片字幕贴卡片底边下方。卡片从统一底边向上生长。
- 卡片高度按内容收紧，不得为了占满安全带固定成大卡。
- 动画时长、位移幅度、缓动和运动气质从 `assets/fullframe-motion-tokens.js` 取值；语义路径和对象结构可按内容生成。不得把普通入场令牌用于标题重排。

## 3. 字幕显示合同

### 3.1 保真优先

- 保留原口播的事实、观点、因果、态度、语气方向、指代关系和信息顺序。
- 默认显示文案等于原口播短语去掉显示标点。只允许删除完全孤立的填充音、紧邻失败重复和已确认的 ASR 错字。
- 不得为了短、整齐或书面化，把“干嘛”改成“做什么”一类同义改写；除非原词确属口误或识别错误并记录修改理由。
- “而且、以及、所以、还有、就是、自己、里面、他就”等连接、指代和推进词默认必须保留。
- “这、那、这个、那个、然后、但是、因为、如果、其实、也、都、才、再、又”等词先判断实际语义；承担指代、转折、因果、递进、强调或推进时必须保留。拿不准就保留。
- 不得删除“？”或把陈述句改成疑问句。显示字幕删除中英文逗号、句号和装饰性标点，只保留真实疑问的 `？/?`。
- 数量、版本和范围优先使用阿拉伯数字；“零到一／0到1”的范围统一显示为 `0~1`。

### 3.2 可追溯修改

每条字幕同时保留 `sourceText` 和 `text`。除空白与标点清理外，只要二者归一化后不一致，就记录 `displayEdits`：

```json
{
  "from": "呃",
  "to": "",
  "reason": "isolated-filler"
}
```

只允许以下理由：

- `isolated-filler`：完全不承载语义的孤立填充音。
- `adjacent-repeat`：紧邻失败重复，保留第一次完整表达。
- `asr-correction`：回听确认的识别错误。
- `numeric-style`：只把范围等数字表达统一成规定格式，例如“零到一”改为 `0~1`。
- `user-approved-removal`：用户对当前成片明确点名要求删除的显示词；同时在该字幕记录 `userApprovedProtectedRemovals`，保留真实 `sourceText`，不得把源口播改掉来绕过审计。

禁止使用“更简洁、书面化、读起来更顺”等理由删改有效口播。受保护连接词只有在用户明确点名当前显示修改时，才允许使用 `user-approved-removal` 例外。

### 3.3 时间、单行和位置

- 字幕沿用原短语完整起止时间；显示清理不改变声音和视频。
- 删除独立填充 cue 后，将时间并入相邻有效 cue，不留下短于 `0.35s` 的闪断。
- 每个时间点只显示一行；最终渲染文字硬宽度不得超过 `820px`，左右必须保留明显安全边距。字符数只用于预警，验收以实际字体、字号、字距的渲染宽度为准。
- 超出 `820px` 时必须按语义和自然气口拆成前后连续两条；不得缩小字号、压缩字距或把文字顶到两侧边缘硬塞。
- 每条字幕标记 `placement: plain` 或 `placement: with-card`。与卡片可见区间重叠的字幕使用 `with-card`，其余使用 `plain`。
- 卡片不得在同一条字幕中途出现或退出。边界落在字幕内部时，先按自然词组拆分字幕，再切换位置。
- 每条字幕最多强调一个连续词组；语气词、连接词和整行文字不得全部标黄，黄色原则上不超过整行的 `40%`。

### 3.4 相邻字幕边界完整性

- 字幕不是按字数切块，而是按“最小语义依赖单元”切分。每个边界都必须同时阅读上一条结尾与下一条开头，确认两边各自形成稳定、可连续阅读的语义短语。
- 切分优先级固定为：`语义依赖完整 > 自然气口 > 字幕宽度与时长均衡`。允许相邻字幕长短不均，不得为了对称、平均字数或平均时长破坏语义。
- 禁止拆开完整词、叠词和固定词组，例如不得把“往往”切成“往｜往”。
- 禁止把主语或代词与其紧接的谓语、否定、情态或判断结构拆开，例如“他｜一定要”“他｜不是”必须整体归入后一条。
- 同样保持否定／程度／情态成分与谓语、修饰语与中心词、介词与宾语、数字与单位等强依赖结构完整。每条字幕不必是完整句子，但不得以需要下一条才能成立的半个词、悬空代词或其他残缺结构收尾。
- 某个短词若依赖下一条的谓语或中心词才能确定含义，将它整体移入下一条；不要因为移动后前一条更短而把它留在前一条。

用户确认示例：

```text
错误：团队里面执行强的人往｜往不一定适合做负责人
正确：团队里面执行强的人｜往往不一定适合做负责人

错误：然后第二个就是他｜一定要去能够跨部门的工作
正确：然后第二个就是｜他一定要去能够跨部门的工作

错误：因为新媒体部门他｜不是一个孤立的部门
正确：因为新媒体部门｜他不是一个孤立的部门
```

严格校验器只负责拦截可确定的拆词和悬空代词模式，不能代替中文语义判断。生成字幕后仍须逐个检查相邻边界，并在连续播放中观看交界点。

## 4. 卡片语义和布局合同

### 4.1 卡片必须增加理解

- 每个候选包装先执行两级必要性测试：删除整个包装后理解不变则使用纯字幕；保留最终静态画面、删除运动后理解不变则删除运动。
- `understandingGain` 必须写出包装相对字幕新增的具体关系、过程、数量、归属或状态理解；“强调重点、丰富画面、增强节奏、提升质感”不算理解增益。
- `whyNow` 必须说明包装为何绑定当前 cue。包装不得在具体对象或关系进入口播之前，仅凭主题结论提前出现。
- 先写清当前口播需要观众理解的语义问题，再选择表达介质，最后才选择动画。固定顺序为：`语义问题 → 卡片／图形／真实素材 → 动画`；丰富和多样性不是目的。
- 每个语义单元先建立 `semanticIntent` 和 `visualModel`，再选择纯字幕、文字卡片、静态图解、动态图形、模拟界面、视觉隐喻、真实素材或它们的组合。这里没有封闭选项表；选择标准是是否降低理解成本。
- `text-card` 是稳定基线和失败回退，不是必须被动画替换的占位物。没有一句话说得清的图形创意、动作映射或合适素材时，保留原卡片。
- 动态表达必须让文字继续承担必要判断或标签，让运动解释进入、流向、替代、划除、连接、数量变化或前后状态等具体语义；不得让动画脱离口播独自表演。
- 整卡淡入、节点依次出现、标题重排和普通箭头绘制属于基础转场，不算语义动画；至少有一个可识别对象必须发生位置、归属、状态、数量或路径变化。
- 全片可以混合使用不同介质。不得为追求形式统一把所有卡片动画化，也不得为追求丰富度给动画、图形或 B-roll 设数量配额。
- 每个动画必须能用一句话回答“它具体解释了哪一层关系、过程、差异或人物状态”。无法回答时，保留已经清楚的简洁卡片，或不加包装；不得为了动画数量强行替换。
- 每张卡只声明一个 `purpose`：`relation`、`contrast`、`process`、`evidence` 或 `conclusion`。
- 字幕负责完整口播，卡片负责组成、关系、流程、证据或结论。当前字幕、`cueText` 的完整句或近义完整句不得成为卡片唯一内容。
- 卡片标题可以把当前口播压缩成短标签或真实问题，但必须服务于后续图解；只把当前字幕换一种说法的标题卡直接删除，也不得提前给出后文答案。
- 删除卡片后不损失理解，或卡片只是在换版式重说字幕时，直接删除卡片。

### 4.2 解释抽象概念

- 遇到“环节很多、体系、环境、能力、流程、公司”等集合概念，使用 `semanticMode: explain`，并在 `displayItems` 展开 `3–6` 个短节点。
- 解释项可以使用该抽象概念直接蕴含、观众可理解的常识性组成。这不算擅自新增观点。
- 禁止加入具体项目并未出现的数据、客户事实、产品能力、承诺、因果或新结论；不确定的专业事实不得靠常识补齐。
- 因果、转化、误区和前后变化优先转为关系、流程或对比，不把判断句原样放进说明框。

### 4.3 组件积木与开放生成

固定的是视觉令牌、人物与字幕安全系统、同步和验收，不是组件目录。以下组件是高频积木，可直接复用，但不是合法组件白名单：

- `single-title`：单个结论或问题，标题居中。
- `title-detail`：标题先居中，说明出现时平滑重排。
- `compare-2`：两个居中节点和一条连续箭头。
- `flow-3`：三个居中节点和两条连续箭头。
- `audit-2`：标题先居中，两个审核结果随后出现。
- `conclusion`：结论先居中，解释行随后出现。
- `media`：真实图片或视频加简短标签。

`media` 只在真实行为、工作场景或人物状态比抽象图形更直接时使用：

- 通常连续停留 `1.5–4s`，内容与当下口播直接对应，不作为无关氛围填充。
- 不遮脸、不抢字幕；必要时使用局部裁切、轻遮罩或短叠化，但不改变人物原片的时间与音频。
- 外部素材必须无水印，并在来源记录中保存素材标题、页面 URL、下载 URL、许可依据和实际使用时间段。
- 审核逻辑、因果链、职责对比等抽象关系若图形更清楚，继续使用卡片或图形，不因已有素材而强行换成 B-roll。
- 仅有关键词相关、只能提供气氛或需要额外说明才看得懂的素材不算“更直接”。找不到语境、权利和动作都匹配的素材时，立即退回文字卡片或简洁图形，不继续用素材站命中结果凑数。

真实素材先判断来源类型，再决定是否使用。固定优先级为：

1. 项目或品牌自有的官方素材；
2. 本片自行实拍、屏幕录制或产品操作录制；
3. 为当前口播定制生成的 AI 场景、3D 场景或界面演示；
4. 许可清楚、语境相符的纪实、公共事实或库存素材。

对中文商业口播，通用欧美办公室库存片只作最后备选。人物地域、服装、办公环境和广告质感与账号语境不匹配时，即使字面相关也不得使用。参考短视频只能拆解其素材类型和制作方法；未取得明确授权时，不得直接抽取、搬运其中的品牌片、新闻片、影视片或 AI 成片镜头。

真实动作更适合短暂接管画面时，优先使用大面积裁切或全画幅短切，通常 `1.2–3.5s`；不得默认塞进带“标题＋说明＋来源署名”的小信息卡。许可允许不署名时，来源只写入工程记录；若许可强制画面署名且会破坏观看体验，优先更换素材，而不是把英文素材站署名硬塞进成片。

AI 生成素材在来源记录中另写生成方式、用途、实际使用时段和必要的权利边界；品牌合作素材另写提供方、资产名称或可追溯文件位置。

已有积木无法清楚承载当前语义时，允许现场生成新的 SVG、CSS 图形、HTML 结构、数据面板、图表、模拟界面、微型系统或视觉隐喻。新组件使用描述性的 kebab-case 名称，例如 `dynamic-system-map` 或 `metric-metaphor`，不得为了通过校验伪装成旧组件。

自定义组件不因“新”而自动属于高风险，也无需逐个向用户确认；但必须同时满足：

- 记录 `visualModel`：画面对象、结构和变化方式；
- 记录 `semanticIntent`：希望观众理解什么；
- 记录 `whyThisVisual`：为什么它比纯字幕或文字卡片更清楚；
- 记录 `motionPlan`：静态理由或对象级语义运动；
- 继续使用黑黄视觉身份、既定安全区、字号底线和动画令牌，不引入新的主题系统。

统计图、表格、柱状图、仪表板、界面模拟、物体动画和视觉隐喻都只是可能结果，不是固定必选类别。同一语义可以有多种视觉答案，优先选择观众无需额外解释就能读懂的一种。

### 4.4 空间和组件细节

- 外框与首个有效内容同帧出现。只有标题时，标题水平和垂直位于卡片视觉中心。
- 后续内容到来时，标题使用重排令牌移动；后续内容在位移后半程交叠淡入。
- 使用 `.dahua-card__stack` 和统一 gap 组织纵向内容，不用绝对定位把说明贴到底边。
- 分阶段卡最终状态中，相邻可见块的边界间距推荐 `16–32px`，硬上限 `36px`。内容少就缩短卡高，不留中间空带。
- 时间轴为 `title-detail`、`audit-2` 和 `conclusion` 记录 `layout.heightPx` 与 `layout.verticalGapsPx`；渲染代码必须使用同一数据。
- 辅助文字至少 `28px`，核心说明 `30–36px`；`20–24px` 仅用于装饰眉题、编号或英文标签。
- 嵌套节点默认水平、垂直居中；内容少时按文字收紧，并保留最小内边距。
- 方向关系只使用 `.dahua-arrow` 的连续线身和 CSS 箭头尖；不得用箭头字符或断开的线身、箭头头部拼接。
- 否定语义使用 `.dahua-strike`；红线必须穿过文字视觉中线，不得落在文字下方成为强调线。

## 5. 时间轴和状态交接

- 音频是唯一主时钟；视觉匹配音频，不改变音频迁就动画。
- 外框和首个标题或节点在锚点短语开始时同帧出现，误差不超过 `±3` 帧。
- 口播逐项列举时，各节点在说到对应词组时出现。
- 口播只说抽象集合词、没有逐项念出解释节点时，标题绑定集合词开始；`displayItems` 作为一组在该概念语义建立后出现，不伪造不存在的逐项语音 cue，也不得早于集合词。
- 后文答案、结论和完整结果不得提前显示。卡片退出覆盖完整语义单元，通常在短语结束后保留 `0.10–0.25s`。
- 同一 `visualSlot` 的顶层卡片和标题不得重叠。前一状态的可见区间必须结束后，后一状态才能开始；语义切换明显时建议保留 `2–4` 帧中性间隔。未声明时默认 `card-band`。
- 同一卡片内部只允许重排令牌规定的不同目标交叠动画；不得让旧标题与新标题同时占据同一位置。
- 真实素材主体通常至少停留 `1.5s`。

## 6. 数据结构

### 6.1 字幕

```json
{
  "id": "cap-08",
  "start": 10.02,
  "end": 13.32,
  "sourceText": "而且很多人他连自己的产品",
  "text": "而且很多人他连自己的产品",
  "displayEdits": [],
  "keywords": ["产品"],
  "placement": "plain"
}
```

### 6.2 卡片和事件

包装单元保存 `component`、`purpose`、`start`、`end`、`understandingGain`、`whyNow`、布局和 `motionPlan`；自定义组件另存 `visualModel` 与 `whyThisVisual`。事件继承组件与结束时间，只需记录 `target`、`event`、`cueText` 和 `start`。

```json
{
  "id": "card-01",
  "visualSlot": "card-band",
  "component": "title-detail",
  "purpose": "conclusion",
  "understandingGain": "把字幕中的抽象公司概念展开为可见的组成关系",
  "whyNow": "从口播开始解释公司包含什么时出现，前面的提问只保留字幕",
  "start": 10.20,
  "end": 14.80,
  "layout": {"heightPx": 200, "verticalGapsPx": [24]},
  "motionPlan": {
    "mode": "semantic-motion",
    "semanticIntent": "信息从标题流向三个组成节点",
    "pattern": "split",
    "actors": ["信息令牌", "组成节点"],
    "motionGain": "分流动作让一个概念包含多个组成的关系可见"
  },
  "events": [
    {"target": "title", "event": "enter-center", "cueText": "什么是公司", "start": 10.20},
    {"target": "title", "event": "reflow", "cueText": "公司包含什么", "start": 12.40},
    {"target": "detail", "event": "enter-overlap", "cueText": "公司包含什么", "start": 12.66}
  ]
}
```

解释型卡片另在卡片级记录 `semanticMode: explain` 和 `displayItems`。子事件如携带 `displayItems`，必须与卡片级完全一致。

`understandingGain` 与 `whyNow` 对所有包装单元必填。`motionPlan.mode` 只允许 `static`、`semantic-motion` 或 `b-roll`。`static` 必须写具体 `reason`；另外两种必须写非空 `pattern` 与 `actors`；`semantic-motion` 还必须写非空 `motionGain`。模式细节见 [fullframe-semantic-motion-patterns.md](fullframe-semantic-motion-patterns.md)。卡片数不少于 `6` 且合格语义动画与 B-roll 都为 `0` 时，严格校验失败；仅允许用户明确批准的顶层 `motionPolicy.staticOnlyApproved: true` 例外。

`component` 必须是非空 kebab-case 名称。基础积木可沿用既有名称；任何自定义名称都合法，但必须补充非空 `visualModel` 与 `whyThisVisual`。`motionPlan.pattern` 同样是开放命名，不要求命中模式清单；基础转场名称仍不得冒充语义动画。

## 7. 工程与返修闭环

- 新版本可保留旧目录，但新目录内部只保留一套最终 CSS、动画参数和数据。
- 固定系统问题先修改本合同、共享资产、时间轴生成逻辑或校验脚本，再重新生成工程；禁止只给当前 HTML 加补丁。
- 局部反馈只修改用户点名范围，其他已确认字幕、卡片、时序和样式冻结。
- 用户要求把既有图片插入已验收视频时，优先保留原图内容，通过裁切、放大、拆分聚焦或遮罩适配竖屏。除非用户明确要求重排或重绘，不得把图片重新制作成 HTML 图表。
- 局部内容修订复制最新验收工程，不执行新建整片工程的从零数据重建；只更新受影响素材、时间轴事件和必要的字幕 `placement`。
- 渲染前运行：

```powershell
python <skill>/scripts/validate_package.py --captions captions.json --timeline production-timeline.json --strict
```

- 机械校验不能判断全部语义和最终画面。首次完整包装完成完整版验收；局部修订只完成 [fullframe-routing-and-acceptance.md](fullframe-routing-and-acceptance.md) 的差量验收。
- 固定系统返修执行五步闭环：共享真源修改 → 工程重生成 → 局部关键帧验证 → 完整发布版重渲 → 最终 MP4 反查。
- 局部内容返修执行快速闭环：复制验收版 → 只改点名区间 → `3–6` 张风险帧 → 一次高质量整片渲染 → 受影响时点与冻结区各反查一帧。不得因局部内容返修重新审计全片。
