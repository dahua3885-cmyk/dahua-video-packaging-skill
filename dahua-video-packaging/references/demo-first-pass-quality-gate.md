# 首版一致性闸门

这份闸门不是审美建议，而是完整渲染前必须满足的项目合同。它用于限制首版自由度，避免每条视频重新发明封面、正文结构和证据节奏。

## 固定场景语法

正文只能从下列模板中选择；同类内容在一条视频内必须复用同一模板，不得每段换一种排版。

| `templateId` | 用途 | 固定信息关系 |
| --- | --- | --- |
| `cover` | 原片封面或已确认发布封面 | 只全屏出现一次；不缩进人物小窗 |
| `topic-overview` | 总起主题 | 总标题 → 一句范围说明 → 当前真实证据 |
| `question-evidence` | “是什么／去哪找／怎么装／怎么创建” | 当前问题标题 → 一句解释 → 对应截图或操作 |
| `gate-intro` | 第 X 关／步／项 | 第一行序号 → 第二行完整任务；下一场必须进入对应案例 |
| `evidence-full` | 账号、作品墙、网页、旧成片 | 真实证据为主，解释为辅；主页与作品墙不得混用 |
| `interview-case` | 人物、收入或采访案例 | 上方身份／结果 → 中部真实人物视频 → 下方解释 |
| `process-build` | 调研、PRD、原型、验证等过程 | 按口播逐项出现，未讲到的节点保持隐藏 |
| `relationship-summary` | 多句话之间的因果、递进或闭环 | 先建立关系，再出现结论；不用逐句换页 |
| `comparison` | 两种以上真实样板比较 | 样板与说明固定对应，不用抽象卡代替样板 |
| `conclusion` | 收束与 CTA | 一页递进完成；人物保留到最后一帧 |

具体文案、截图裁切和当前案例可以变化；模板的信息层级、人物、字幕、证据类型和已确认模块不得临场变化。

## 强制项目文件

在工程根目录生成 `first_pass_gate.json`。它同时承担：源片与基准版本校验、允许修改范围与冻结层、封面边界、语义触发、真实证据、同层持续、逐项出现状态和代表性检查产物。

初始化：

```powershell
python -X utf8 "<本 Skill 目录>/scripts/validate_first_pass_gate.py" init "<工程目录>" --workflow evidence-demo --source-video "<源视频>" --layout-mode <vertical|landscape>
```

返修已有版本时增加 `--baseline-version "<最近一次完整且已确认的成片或工程主文件>"`。填写并准备好样片、抽帧或并排检查图后运行：

```powershell
python -X utf8 "<本 Skill 目录>/scripts/validate_first_pass_gate.py" validate "<工程目录>" --workflow evidence-demo
```

校验未通过时不得渲染完整预览、不得复制到成片目录、不得对用户表述为“已经做好”。

## 代表性样片必须覆盖

1. 封面最后一帧 → 正文第一帧；
2. 第一次真实证据触发；
3. 本片使用的每一种 `templateId` 至少一次；
4. 每个“关卡介绍 → 案例”边界；
5. 结尾收束页；
6. 最后一帧人物、字幕和底图。

每个检查点都必须在 JSON 中登记实际存在的图片、联系表或短样片路径。只写“已检查”不算通过。

## 首版通过定义

- 基准版本、封面、人物、字幕和用户认可模块已冻结。
- 账号用主页、作品用作品墙、人物案例用对应原视频、旧案例用真实旧成片。
- 画面从对象第一次被说出的播放帧进入；字幕换句不重建相同证据。
- 所有并列项和过程状态按口播逐项出现。
- 相同内容复用相同模板；没有临时新造页面语言。
- 发布版清晰度、边界抽帧和最后一帧均有真实检查产物。
