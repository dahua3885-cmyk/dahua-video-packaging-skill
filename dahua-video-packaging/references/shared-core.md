# 三种模式共享核心合同

## 0. 严格视觉配置与多用户隔离

- 默认唯一视觉真源是 `assets/portable-profile.json` 的 `dahua-portable-v1@1.0.0`。
- 每个工程必须拥有独立的 `portable_project.json` 和 `.dahua-portable/` 快照；不同用户、不同项目不得共享可变 CSS、缓存、时间轴或输出目录。
- 只使用 Skill 内附带且有许可证的 Noto Sans SC 与 Smiley Sans。不得依赖系统字体、用户名目录或旧工程字体。
- 默认禁止新增颜色、字体、缓动和动效家族。用户明确要求改变视觉系统时，新建 profile 版本；既有项目继续锁定原版本。
- 公开仓库、日志和示例不得包含用户名、邮箱、密钥、Cookie、客户素材绝对路径或私人黄金样片路径。

## 1. 事实源与授权边界

- 原视频、原音轨、转写、用户指定标题、参考素材和用户已确认版本是唯一事实源。
- “包装”默认只授权增加视觉信息层，不默认授权删改音频、重排口播、删除停顿、替换原字幕或改写用户已确认文案。
- 每次返修先记录 `baselineVideo`，再逐项写明可变层和冻结层。未点名的层一律冻结。

## 2. 唯一模式与合同文件

- 一个版本只能使用 `fullframe`、`small-window`、`evidence-demo` 中的一种模式。
- 工程根目录必须存在 `packaging_mode.json`；正式渲染前必须通过 `validate_mode_contract.py validate`。
- 工程根目录还必须存在 `portable_project.json`；正式渲染前必须通过 `portable_project.py validate` 和 `validate_portable_visuals.py`。
- 需求改变到必须切换模式时，创建新版本目录并重新初始化合同，不能直接在原版上覆盖。

## 3. 时间轴与语义

- 先生成可核对的语义时间轴，再设计卡片、素材和动效。
- 卡片内容必须是口播的提炼，不得出现口播没有支撑的结论。
- 并列概念、步骤和数字按口播节点逐项出现；当前没讲到的项保持隐藏。
- 真实截图、录屏和案例视频必须与当前语义对应，不得为了“丰富”而错配。

## 4. 封面、版本与边界

- 封面只服务发布选帧；不得把正文向后平移成额外片头。
- 用户指定原片前几帧、既有蓝色封面或参考视频封面时，严格复用指定源。
- 新一轮修改必须另存版本；交付时清楚标记成片、工程、基线和修改范围。

## 5. 发布与验收

- 默认优先 1440×2560 的 2K 竖屏发布版；用户指定其他规格时服从用户。
- 必查：分辨率、帧率、时长、逐帧解码、字幕安全区、人物遮挡、素材清晰度、框选准确度、音轨完整性。
- 返修若未授权声音变化，应以音轨哈希或等价方式确认音频与基线一致。
- 最终抽检必须来自成片 MP4，而不是只看 HTML 或中间帧。
