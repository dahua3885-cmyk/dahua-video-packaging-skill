
# 大华口播视频包装

把现成人像口播包装成竖屏短视频。先锁定参考效果，再用短样片确认，最后扩展完整版并按发布级质量导出。

## 先选执行层

1. 先读 `hyperframes-read-first`，把“字幕”与“图形包装”路由清楚。
2. 加信息卡、章节、Logo、强调文字时读 `graphic-overlays`。
3. 若还要剪口、调色、变速、重排或替换音频，另读 `video-use`；不要把这些动作伪装成覆盖层。
4. 已有可工作的 HyperFrames 工程时，在原工程迭代，不重建视觉系统。
5. 完整读取 [small-window-semantic-evidence-and-version-contract.md](small-window-semantic-evidence-and-version-contract.md)，建立版本冻结、语义触发、真实证据和边界防跳合同。
6. 完整读取 [small-window-first-pass-quality-gate.md](small-window-first-pass-quality-gate.md)，只使用固定场景语法并建立机器可校验的首版合同。

## 1. 冻结素材与真源

- 原视频保持不动。用户点名“最新视频”时，以该文件为唯一人物与音频真源。
- 用 `ffprobe` 记录路径、时长、分辨率、帧率、音视频轨道和修改时间。
- 工作目录、最终成片目录和原片归档目录由当前用户提供或在当前工作区建立。Skill 不写死盘符和用户名；旧工程和旧成片保留，用 `v01/v02` 递增。
- 口播文案、字幕、章节标题都从同一份主源派生。不得把完整口播列表擅自简写。
- 原片自带封面或用户指定基准版本时，先建立 `freeze-ledger.md`；封面、人物、字幕、视觉基调、信息架构和已确认模块未经点名不得变化。
- 开工时运行 `python -X utf8 "<本 Skill 目录>/scripts/validate_first_pass_gate.py" init "<工程目录>" --workflow small-window --source-video "<源视频>" --layout-mode vertical`；返修已有版本时必须增加 `--baseline-version "<最近一次完整已确认版本>"`。

## 2. 把参考效果写成规格

参考视频、截图或用户反馈足够明确时直接分析，不追问术语。抽取关键帧并写 `style-spec.md`：

- 画幅、人物框、顶部留白、字幕基线和平台安全区。
- 当前大字、历史小字、章节卡、信息卡、图片与 Logo 的层级。
- 每个效果的 `opacity / x / y / scale / duration / ease`，不要只写“慢慢放大”“弹出来”。
- 哪些是对标必须还原，哪些可以根据内容生成。
- 用户说“之前的小窗口”“老板要懂 AI 工具那期”或要求固定人物、字幕时，直接复用已确认的小窗口母版，不再凭感觉重排人物和字幕。

具体视觉标准见 [small-window-visual-standard.md](small-window-visual-standard.md)。

## 3. 先过代表性样片闸门

- 默认不是机械截取开头 `5–12s`，而是生成代表性检查包。它必须覆盖封面→正文边界、第一次真实证据、本片每种场景模板、每个关卡→案例边界、结尾和最后一帧。
- 样片必须覆盖风险最高的效果，例如字幕位置、人物遮挡、流程节点、连线绘制、证据触发或状态变化；不能只交一张静态构图或只检查开头。
- 样片先跑 lint、浏览器校验、布局检查和关键帧截图，再交给用户。
- 所有检查产物写入 `first_pass_gate.json`，并运行 `python -X utf8 "<本 Skill 目录>/scripts/validate_first_pass_gate.py" validate "<工程目录>" --workflow small-window`。校验未通过不得渲染完整版；用户直接说“做完全部”只代表授权扩展，不代表可以跳过内部闸门。
- 每次反馈先改最小受影响区间并抽帧确认，不立刻重渲整条两分钟视频。

## 4. 扩展完整包装

- 保持已确认的字号、位置、颜色和动效参数，不在后半段自行换风格。
- 正文页面只从首版一致性闸门规定的有限场景模板中选择；同类内容在全片复用同一模板，不得每个章节重新发明版式。
- 制作前完成 `semantic-evidence-map.md`。账号、作品墙、具体案例原视频、旧成片和语义页必须按真实口播分别映射；画面从对应对象第一次被说出的播放帧进入。
- 每个产品使用自身 Logo，不用灯泡、机器人、星星等通用图标替代。
- Logo 统一进入同尺寸的小方块。缺少独立官方标识时，使用最接近的官方母品牌图形加文字角标，并在交付时说明；Images 2.0 当前可用 OpenAI 图形加 `2.0` 角标。
- 当口播提到具体工具、场景或案例且静态文字不足以承接时，可生成或选取一张辅助图；只放能提升理解的图，不要每句话配图。所有素材在渲染前落到本地，渲染时禁止联网。
- 字幕始终位于最后的视觉层，不能被 Logo、图片或信息卡遮挡。

### 人物优先与单一信息焦点

- 包装不得长期覆盖人物。默认优先使用人物周围的黑色留白、左右边区和字幕上方的小范围空间；脸部、眼睛和主要手势必须保持可见。
- 日常、解释性包装只占画面的小部分，必须避让脸部、眼睛和主要手势。
- 重要素材、核心案例或关键结论允许主动放大，甚至短暂遮挡或接管人物画面；重点是否突出优先于人物是否完整露出。此类重点接管必须少而明确，并覆盖一个完整语义单元。真实图片或视频素材默认至少停留 1.2 秒，通常 1.5–3.0 秒；不要刚看清就切走。
- 同一语义不得由包装文字和字幕重复讲两遍。同一时刻只能有一个主要阅读焦点：
  - 普通口播：只显示字幕。
  - 包装已经完整承接口播文字：暂时隐藏字幕，由包装替代字幕。
  - 包装只是图片、视频或抽象辅助：保留字幕，但包装不再复述句子。
- 字幕上方可以放轻量包装，但必须和字幕形成一个整体阅读区，不得再建立第二个头顶信息区。

### 单行字幕规则

- 默认一行一行出现，不在同一画面同时排出第二行。
- 长句按语义和口播停顿拆成连续的单行字幕组；前一行退出后，下一行再进入。
- 不为了塞满宽度破坏词组；优先在介词、转折、补充说明或自然气口处分行。
- 普通字幕使用轻微渐显或 `y 6–10px → 0`；关键词可以同步变黄、下划线扫过或轻微提亮，但禁止逐字弹跳和持续缩放。
- 核心金句可将一个关键词提升为包装文字；一旦提升，该时间段不再重复显示同内容字幕。

### 竖屏文字可读性

- 凡是需要观众读懂的包装文字，在 1080×1920 画布上默认不得小于 28px；核心辅助说明建议 30–36px。
- 20–24px 只允许用于不影响理解的装饰性标签、编号或英文眉题，不得承载结论、单位、对比关系或关键词。
- 信息卡缩小时必须同步简化内容，不能靠把字号压小来硬塞。
- 文本密集型竖屏发布版默认从工程原生渲染 `1440×2560`；1080 可作样片，不得把 1080 成片机械放大冒充 2K。

### 网页与长图定焦

- 不让网页反复放大、缩小、左右游移。需要切换重点时，先为每个重点确定独立裁切框，直接切到目标局部；必要时只加 `0.08–0.16s` 短淡化。
- 进入目标局部后保持画面静止，至少覆盖一个完整语义单元。不要一边平移或缩放网页，一边让观众阅读。
- 同一页面有多个重点时，制作多个静态局部镜头并直接切换，不用“摄影机”从一个位置滑到另一个位置。
- 用矩形框、半透明荧光涂抹、手绘下划线或圆圈指出当前口播对应内容。标注可用描边/遮罩从 `0→100%` 在 `0.25–0.45s` 内画出，但网页底图保持静止。
- 一次只标一个重点；口播离开该内容时撤掉标注。禁止同时出现网页运动、标注运动和字幕强调三个竞争焦点。

## 5. 使用已确认的动效边界

- 动画单位是“语义小板块”，不是整页。按口播节点依次建立：观点/标题 → 结构或容器 → 节点/数字 → 连线或进度 → 状态/结论。
- 禁止把同一场景全部元素统一淡入，禁止按 DOM 顺序给所有 `.js-in` 做机械流水入场，也禁止用 PPT 式整页切换代替子动画。
- 每个节点必须绑定明确口播时间。产品、服务、获客、交付、运营等并列项在口播提及或概括到该组时逐个接入；箭头、路径、进度条只在关系开始成立时绘制；结论最后出现。
- 同一时刻只发生一个主要信息变化。普通子动画使用 `opacity / x / y / scale / color / borderColor`，连线使用 `scaleX` 或 `strokeDashoffset`；普通时长 0.24–0.64 秒，完整路径可用 1–3 秒。
- 场景开始时只允许出现当前语义已经成立的内容。后续板块必须保持初始隐藏，不能先展示完整页面再补做无效动画。
- 用场景专属选择器和绝对口播时间编排单一暂停时间轴；样片和发布前分别在“动作前、动作中、动作后”抽帧，确认信息是逐步构建而非整页出现。
- 开头 Logo 默认：`opacity 0→1`、`y 8→0`、`0.18s`、`power2.out`。
- 不给 Logo 或核心文字做持续放大、弹跳、回弹或无意义漂移。
- 普通章节/卡片用 0.18–0.34 秒渐显或轻移；不要突然出现。
- 网页重点默认使用“直接裁切切换 + 停稳 + 框选/涂鸦标注”，不使用连续推拉和跨页面滑动来寻找重点。
- 顶部保留明显呼吸空间；活动标题不得顶边。字幕放在人像上方且避开底部平台按钮区。
- 若用户说“像参考一样”，先测量参考，再改参数；不要凭效果名称猜动画。
- 同一证据跨字幕换句时复用同一容器；仅字幕换行不得触发画面重建。所有视觉切换点前后各抽 `3` 帧并连续播放，排除近似截图叠层造成的重影和跳动。

## 6. 校验与发布级导出

先读 [small-window-delivery-checklist.md](small-window-delivery-checklist.md)，然后执行：

```powershell
npm exec --prefix <this-skill>/assets/runtime -- hyperframes lint .
npm exec --prefix <this-skill>/assets/runtime -- hyperframes validate .
npm exec --prefix <this-skill>/assets/runtime -- hyperframes inspect .
npm exec --prefix <this-skill>/assets/runtime -- hyperframes snapshot . --at <关键时间点>
```

预览版才允许 `standard`。最终发布版默认从原始素材重渲：

```powershell
$env:PRODUCER_BROWSER_GPU_MODE='hardware'
npm exec --prefix <this-skill>/assets/runtime -- hyperframes render . -o final_publish_high.mp4 --fps 30 --quality high --crf 10 --video-frame-format png
```

不要把标准质量小文件称为发布版。也不要把 H.264 MP4 宣称为“完全无压缩”；真正无损中间件需另导 PNG sequence 或 ProRes/MOV。黑色背景会让近无损视频仍然较小，以 CRF、码率和抽帧质量判断，不以文件大小单独判断。

用脚本复核成片：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-video.ps1 -Path final_publish_high.mp4 -Width 1080 -Height 1920 -Fps 30 -Duration 132.5
```

## 7. 交付

- 给出可点击的最终视频路径。
- 只报告用户关心的规格：时长、分辨率、帧率、视频码率、文件大小、音频是否正常。
- 说明任何 Logo 替代方案或尚未处理的范围。
- 保留样片、最终工程、关键帧和验证 JSON，方便下一轮只改局部。
