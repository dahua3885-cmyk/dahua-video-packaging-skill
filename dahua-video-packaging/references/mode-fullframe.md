
# 大华全画幅口播包装

把已剪好的竖屏人像口播包装成发布级视频。保持人物原尺寸和原构图；字幕承担完整阅读，视觉包装只增加理解。

## 核心原则：固定身份，受控表达

- 固定黑黄视觉身份、字幕系统、人物构图、安全区、语音同步、可读性和验收标准。
- 组件内容可以按语义重组，但颜色、字体、圆角、线宽、安全区、缓动和动效家族必须来自 `dahua-portable-v1@1.0.0` 白名单。
- 固定推理链：`口播文案 → 理解语义结构 → 选择允许的视觉模型 → 复用固定积木 → 设计白名单内的必要运动 → 验证理解增益`。
- 统计面板、柱状图、表格、流程图、系统图、模拟界面、物体变化、视觉隐喻和 B-roll 都可承载内容，但不得借此创建新的视觉语言。
- 没有比文字更清楚的视觉模型时，回退到文字卡片或纯字幕；不能为了显得丰富而做动画。

## 理解增益硬门槛

- 包装不是字幕的摘要层。若删除整张卡片、图形或素材后，观众对当前口播的理解没有任何损失，直接删除该包装，保留纯字幕。
- 标题或卡片若只是当前字幕、`cueText` 或口播结论的近义压缩，即使版式和动画完整，也视为零理解增益，禁止出现。
- 包装只在需要被看见的对象、关系、过程、数量或状态进入口播时出现；不得为了预告主题，在语义尚未建立的前几秒提前占位。
- 保留包装后，再执行一次“去掉运动”测试：若只看最终静态画面也能得到相同理解，删除语义动画，改为静态图解；不得为了动而动。
- 每个包装单元必须记录 `understandingGain` 和 `whyNow`；`semantic-motion` 另记录 `motionGain`。无法具体填写时，说明该包装或动画没有存在必要。

## 真源分工

先按职责判断，不把多个文件当成可任选的版本：

- 用户对当前成片的最新明确反馈：当前任务最高优先级。
- [fullframe-production-contract.md](fullframe-production-contract.md)：字幕、卡片、时间轴和工程行为合同。
- [fullframe-visual-standard.md](fullframe-visual-standard.md)：包装该不该出现、该解释什么的视觉语义。
- [fullframe-semantic-motion-patterns.md](fullframe-semantic-motion-patterns.md)：语义动画机会扫描、合格动作模式和非合格基础转场。
- `assets/fullframe-contract.css`：坐标、字号、颜色、间距和组件样式的可执行数值真源。
- `assets/fullframe-motion-tokens.js`：动画数值真源。
- [fullframe-routing-and-acceptance.md](fullframe-routing-and-acceptance.md)：模式路由与最终验收清单。
- [fullframe-v10-first-pass-standard.md](fullframe-v10-first-pass-standard.md)：普通包装请求的默认完成定义和首版回归闸门。

同一职责若出现不一致，停止渲染并同步文件，禁止挑一个方便的继续做。历史工程和已认可成片只提供整体观感，不覆盖上述真源。

## 必须读取

- 新建整片包装、改变全片结构、修改字幕系统或固定视觉系统：完整读取生产合同和视觉标准。
- 新规划或全片返修语义动画：完整读取语义动画模式，不得只用文字节点入场冒充语义动画。
- 普通“做包装”请求或首次完整交付：完整读取 V10 首版交付标准。
- 判断两套包装模式或首次完整交付：完整读取路由与验收。
- 已验收工程的局部加图、换图、删卡或改一个时间段：读取本文件的“局部素材插入／局部返修快速通道”和 `fullframe-routing-and-acceptance.md` 的“局部修订验收”；只有改动触及字幕合同、固定视觉令牌或新增复杂语义动画时，才加载相应完整参考。不得为了局部插图重新读取和执行 V10 首版全量闸门。
- 实际制作视频：读取 `hyperframes-read-first`，按其路由使用 HyperFrames。
- 只做 Skill 审计、不制作视频时：无需加载 HyperFrames。

## 默认完成定义

- 用户附上已剪好的口播视频并说“做包装”时，直接完成整条视频，默认目标是 V10 首版标准。用户不需要再次复述字幕、卡片、间距、错峰和数字规则。
- 用户指向已经验收的包装版并点名“加这张图／把这两张图放进去／换掉这里的卡片／只改这一段”时，默认解释为局部修订，不重新设计整条视频，不重做未点名图表，不复查未受影响的字幕与语义单元。
- 不把方案、字幕稿、故事板、10 秒样片、低清预览或尚未验收的渲染当成交付。首次高质量渲染若已通过对应验收可直接交付，不得为了“再确认一次”机械重渲。
- 优先复用已确认积木。语义需要时可组合新的 SVG 或 HTML 内容结构，但样式与运动只能调用固定配置；不得加入未登记的色值、字体、发光、弹跳、粒子、弹簧或持续循环。
- 用户说“丰富一点”时，必须主动扫描并实现口播中可被动作解释的关系、过程和状态变化；不设置动画数量指标，但完整长视频不得因为保守而退化成全程文字卡片。
- 只有用户明确说“先测试／测试 10 秒／先做样片”时，才允许在本轮停在样片。

## 执行流程

### 0. 先区分局部修订与完整包装

#### 0A. 局部素材插入／局部返修快速通道

- 触发条件：用户提供已包装成片或已验收工程，并明确点名不超过 `3` 个素材、`2` 个连续区间或少量字幕／卡片修改，且不要求改变全片视觉系统。
- 从最新验收工程复制新版本，保留既有 HTML、CSS、字幕、时间轴和渲染入口；只改用户点名区间。禁止把局部修改升级成重新建工程、重新语义扫描全片或重新设计既有组件。
- 用户说“把图片加进视频”时，图片本身是内容真源。默认只做裁切、放大、分屏聚焦、背景遮罩和现有令牌内的简洁入退场；横图在竖屏看不清时，优先把同一原图拆成连续局部聚焦镜头，不得擅自把原图内容重写成 HTML 图表。只有用户明确要求“重新排版／重做成图表”时才重绘。
- 只核对受影响区间的字幕位置、卡片边界、人物遮挡和素材可读性；未点名区域冻结，不重新逐条审查字幕、卡片必要性或动画机会。
- 运行一次严格数据校验和一次 HyperFrames 检查；随后只抽 `3–6` 张局部风险帧，覆盖进入、稳定态、切换／退出及一张未修改对照帧。首轮通过后禁止继续扩大抽帧数量。
- 通过后只执行一次高质量整片渲染。首次渲染命令超时不得短于 `600s`，或上一版实际渲染时间的 `2` 倍，取较大者；禁止因外层超时过短中止后重复渲染。
- 最终只做受影响时点反查、原音轨一致性、时长／编码和整文件解码。局部修改目标用时为 `10–15` 分钟；若预计超出，先收缩为原图裁切／分段聚焦，不自行扩大设计范围。

#### 0B. 新建完整分享类包装快速通道

- 用户没有要求改变固定视觉系统，且内容属于普通分享类口播时，直接复用已经通过验收的单时间轴骨架；不得重新发明字幕生命周期、时间轴注册或渲染入口。
- 主时间轴必须在主 HTML 内同步创建并完成注册。禁止先注册空占位时间轴、再由外部脚本替换；禁止在大量抽帧后才验证时间轴是否真正驱动字幕和卡片。
- 先完成数据、组件和机械校验，再运行 `scripts/run_fast_preflight.ps1`。它只检查普通字幕帧、卡片中间态和结尾帧；三帧全部正常后，才允许批量风险抽帧。
- 普通 H.264 竖屏原片默认直接进入 HyperFrames。只有实际出现随机寻帧失败、黑帧或关键帧稀疏证据时，才生成密集关键帧副本。
- 转写前只探测一次可用引擎。GPU 运行库未通过探测时直接使用已缓存的 CPU production 模型，不允许先后尝试多个必然失败的路径。
- 完整风险帧通过后只运行一次 `high / CRF 10 / PNG` 发布渲染。禁止边改边高质量渲染。

### 1. 冻结源文件、范围和已确认部分

- 用用户指定的最新版 MP4 作为人物和音频唯一真源；默认不剪辑、不调色、不变速、不降噪、不换音频、不缩放人物。
- 只有用户同时要求剪口、调色、变速、重排或改音频时才调用 `video-use`。
- 用 `ffprobe` 记录源路径、时长、分辨率、帧率、音视频轨和修改时间。
- 把反馈分类为固定系统、条件变化或本片一次性内容。局部反馈只改点名区域；其余已确认内容冻结。
- 工程、成片和原片目录由当前用户明确提供或在当前工作区内建立；历史版本递增保留。Skill 不假定盘符、用户名或共享全局目录。

### 2. 建立干净工程和单一数据层

- 新建完整包装工程时复制两个 `assets/` 文件，不复制历史工程的版本覆盖 CSS。
- 局部修订时复制最新验收工程作为新版本，继续维护其中唯一的 CSS、数据与渲染入口；不得借“工程干净”为由从零重建。
- 只维护 `source.mp4`、`captions.json`、`production-timeline.json` 和一套最终组件代码。
- 字幕、HTML、动画、故事板和验收时点从同一份数据生成或核对，禁止多份文案和多套时间轴。
- 同一视觉属性只能有一个定义；禁止追加 `v02 fix`、`v03 override` 等层叠补丁。

### 3. 先完成保真字幕

- 从原片建立逐词或逐短语时间轴，再生成显示字幕。
- 默认只删除孤立填充音、紧邻失败重复和显示标点；不得为了短、整齐或书面化吞掉连接词、指代词、推进词和有效口语。
- 字幕边界必须保持“最小语义依赖单元”完整，优先级固定为：`语义依赖完整 > 自然气口 > 字幕宽度与时长均衡`。不得拆开完整词、叠词、固定词组，也不得把主语或代词与其谓语、否定／情态成分与其谓语、修饰语与中心词等强依赖结构分到两条字幕。允许前后长短不均，禁止为了视觉整齐把半个词或悬空的代词留在上一条。
- 每条字幕保留 `sourceText`、`text`、`start`、`end`、`keywords`、`placement`；发生非标点修改时记录 `displayEdits` 和理由。
- 全片只用 `.dahua-caption`。`placement: plain` 使用无卡片位置，`placement: with-card` 使用有卡片位置；不得复制第二套字幕样式。
- 卡片边界不得落在同一条字幕中间；先按最小语义依赖单元和自然气口拆分，再切换位置。

### 4. 先做语义建模，再建立解释型包装

- 先对每个候选单元执行双删除测试：删除整个包装是否损失理解；保留最终画面但删除运动是否损失理解。第一问为否则用纯字幕，第二问为否则使用静态图解。
- 逐段提取真正需要解释的语义结构：数量、比例、趋势、差距、关系、层级、流程、机制、状态变化、积累、损耗、替代、空间方向、人物行为或抽象概念。
- 为每段先写一句 `semanticIntent`，再构思能让观众一眼看懂的 `visualModel`。先回答“画面里有哪些对象、它们是什么关系、什么变化最关键”，再决定是否复用组件。
- 在画面规划前单独执行视觉与动画机会扫描，并按 [fullframe-semantic-motion-patterns.md](fullframe-semantic-motion-patterns.md) 的开放式方法构思；禁止把文档中的示例名称当成可选菜单。
- 根据理解成本直接选择纯字幕、文字卡片、静态图解、动态信息图、模拟界面、视觉隐喻或真实素材，也允许组合。动作关系明确时，默认让运动承担具体语义变化。
- 已有组件能清楚承载就复用；不能清楚承载时，现场生成新的 kebab-case `component`，而不是把语义硬塞进最接近的旧模板。
- 所有包装单元必须记录 `understandingGain` 和 `whyNow`；自定义组件另记录 `visualModel`、`semanticIntent`、`whyThisVisual` 和 `motionPlan`，并验证它比纯文字更快、更准或更省解释。
- 文字卡片是默认回退方案，不是待淘汰的旧形式。没有清楚的图形创意、动作映射或语境匹配素材时，保留原卡片；禁止为了“丰富”强行替换。
- 语义微动画可以发生在文字卡片内部，例如进入、流向、替代、划除、前后状态变化；它必须强化卡片已经说清的关系，不能独立表演。
- 真实行为、操作过程或人物状态确实比抽象图形更直观时才使用 B-roll。找不到中文账号语境相符且权利清楚的素材时，退回文字卡片或简洁图形，不用欧美库存片凑数。
- 第三方真人素材默认不得露出可辨识正脸；优先选背影、手部、屏幕操作和环境动作。素材其余部分合适但含正脸时，必须通过裁切或遮挡彻底移除正脸后再使用；无法干净处理就弃用。
- 整条视频允许字幕、文字卡片、卡片微动画和短 B-roll 混合出现；丰富度来自介质匹配，不来自全片统一换成某一种形式。
- 每个包装单元必须在 `production-timeline.json` 写入 `motionPlan`。`semantic-motion` 必须额外写 `motionGain`，说明运动相对最终静态画面具体增加了什么理解。淡入、滑入、文字节点依次出现、标题重排和普通箭头绘制只是基础转场，不得填写为 `semantic-motion`。
- 卡片数不少于 `6` 的完整视频若合格 `semantic-motion` 与 `b-roll` 合计为 `0`，严格校验必须失败；只有用户明确要求全静态并在时间轴记录 `motionPolicy.staticOnlyApproved: true` 时例外。
- 每张卡只声明一个 `purpose`，只允许 `relation / contrast / process / evidence / conclusion`。
- 字幕完整说出口播；卡片展示组成、关系、流程、证据或结论。只复述字幕、删掉后不损失理解的卡片直接删除。
- “环节、体系、环境、能力、流程、公司”等集合概念使用 `semanticMode: explain`，展开 `3–6` 个短节点；不得把抽象原句换行塞进卡片。
- 解释节点可以使用被抽象概念直接蕴含的常识性组成，但不得编造项目事实、数据、承诺、因果或口播之外的新结论。
- 同一视觉位置的前后状态必须互斥：前一状态完整退出后，后一状态才入场。禁止标题重叠、卡片打架和后文提前出现。
- 分阶段卡使用统一重排令牌；最终状态的卡高和纵向间距写入时间轴，内容少就缩卡，不留空带。

### 5. 校验后再扩展和渲染

- 数据完成后运行：

```powershell
python <this-skill>/scripts/validate_package.py --captions <captions.json> --timeline <production-timeline.json> --strict
```

- 有错误时禁止渲染。机械校验通过后，再人工检查字幕保真、卡片必要性、解释边界和画面遮挡。
- 新建完整分享类工程先运行三帧烟雾测试：一张纯字幕、一张卡片中间态、一张结尾退场。三帧中任一张缺少应有字幕或包装时，立即检查时间轴注册与 clip 生命周期，不得继续抽取 20 张以上风险帧。局部修订按 0A 的 `3–6` 张差量风险帧执行，不升级为全片抽帧。
- 已确认积木与自定义语义组件都可直接进入完整版。自定义结构本身不等于高风险；风险来自改变视觉身份、遮挡人物字幕、降低可读性或引入不稳定渲染。
- 确实需要新字体、新颜色、改变固定安全系统、复杂大面积接管时，先做内部风险预览；只有它会改变稳定视觉系统时才向用户确认。
- 用户明确要求“完整视频”或“全部做完”时，任何风险预览都只是内部检查节点，不是最终交付。

### 6. 发布闭环

- 返修固定系统问题时执行：共享真源修改 → 工程重生成 → 受影响时点抽帧 → 完整高质量重渲 → 从最终 MP4 再抽帧。
- 局部内容修订时执行：复制最新验收工程 → 只改点名区间 → `3–6` 张差量风险帧 → 一次完整高质量渲染 → 从最终 MP4 只反查改动时点和一张冻结区对照帧。
- 发布版使用：

```powershell
$env:PRODUCER_BROWSER_GPU_MODE='hardware'
npm exec --prefix <this-skill>/assets/runtime -- hyperframes render . -o final_publish_high.mp4 --fps 30 --quality high --crf 10 --video-frame-format png
```

- `standard` 只用于预览。若源视频关键帧稀疏，可制作仅供渲染的密集关键帧副本，但人物与音频真源仍是原片。
- 渲染后把原片音轨以 stream copy 重新挂回发布版；检查编码、时长、分辨率、帧率、音轨和整文件解码。
- 按路由与验收文件检查全部用户纠错时点、典型卡片和跨期视觉一致性。工程快照、区间样片和旧整片都不能代替最终 MP4。
- 首次完整包装再按 V10 首版回归闸门逐项检查。局部修订只按差量验收，不重复执行全量首版闸门；任一受影响项失败时继续内部返修。
