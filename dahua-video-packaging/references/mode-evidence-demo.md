
# 大华 Skill / 网站 / 工具演示视频包装

把已剪好的口播视频做成“真实页面负责举证，人物负责讲解，字幕负责兜底，动画负责引导”的发布级演示视频。

## 路由边界

- Skill、网站、工具、工作流、报告或数字产品演示，且真实界面是主要证据：使用本 Skill。
- 普通口播、人物保持原尺寸、包装只是辅助：使用 `fullframe`。
- 用户明确要人物缩小给大型信息卡让位，但没有真实网页或操作作为主视觉：使用 `small-window`。
- 同时出现“人物小窗”和“网页／工具演示”时，以真实界面主视觉为判断依据，使用本 Skill。

用户明确说“按这个 Skill 包装”即视为已确认固定版式与只包装策略，不再重复询问人物大小、字幕样式或黄框样式。只有源片、对标、输出画幅或是否允许剪口播仍不明确时才提问。

## 不可变的创作原则

1. 先做逐字时间轴，再做画面。禁止先堆素材、后找口播对应关系。
2. 口播决定画面。每个页面必须是当前句子的操作、证据、例子或结果。
3. 标准演示模式的开头总起句不提前进入第一个案例；横屏比较模式若主题本身就是“两种／三种包装”，允许开头同时展示全部真实样板，但必须编号且只承担总览，不提前讲解某一项。
4. 横屏默认严格执行固定版式合同。人物 `210×352, x=1676, y=690`；字幕 `44px` 白色粗体、底部居中短黑胶囊；不得把这些参数当作创意项。
5. 竖屏默认严格执行固定版式合同。人物 `450×445, x=580, y=1285`；字幕 `960×88, x=60, y=1165`；文本密集型发布版原生渲染 `1440×2560`，不得把 1080 成片直接放大。
6. 网页、Markdown、软件界面和结果页面是主视觉；人物只作为角落讲解员。
7. 找重点靠直接切镜头；指出重点默认只用固定样式细黄框；让观众理解靠稳定停留。其他标注形式只有用户明确要求时才使用。
8. 黄框是证据指针，不是包装装饰。默认细黄框、一次一个、只在关键词到达后出现；页面已经清楚时不加。
9. 扫描、滚动、框选、点击、执行和结果变化只要承担因果关系，就必须保留真实运动；过程太慢时加速真实录屏，不得换成静态截图组。
10. 禁止反复放大、缩小、左右寻找重点和无目的连续滚动。每段必要滚动必须记录方向、起点、终点和口播触发字。
11. 页面比例按场景自适应：操作页看全、分析页看清、结尾页看完整。页面构图允许发挥，但必须主动避开固定人物、字幕和标注安全区。
12. 评论、数据、统计和结果必须来自真实页面。页面没有的数据不得补造；可用定性归纳，但必须标清边界。
13. 辅助录屏必须先清洗安全区间，成片任何一帧不得出现 OBS、错误窗口、录屏控制栏或隐私界面。
14. 合成顺序固定为页面 → 页面运动／黄框 → 人物 → 字幕。人物之后禁止任何全屏灰层、颜色层或调色。
15. 同一证据跨多句持续时复用同一个容器；字幕换句不等于换画面。所有画面切换点前后各抽 `3` 帧，禁止近似截图叠层造成重影或跳动。
16. 正文页面只从首版一致性闸门规定的有限场景模板中选择；同类内容复用同一模板，不得每个章节重新发明版式。
17. 全片渲染前必须建立并通过 `first_pass_gate.json`。代表性样片不能只看开头，必须覆盖封面边界、第一次证据触发、每种场景模板、每个关卡→案例边界、结尾和最后一帧。

## 执行顺序

1. 冻结最新版源视频、真实网站／文档／界面和用户已确认部分；记录源片媒体信息和主音频校验值。
2. 先选择 `evidence-demo` 标准演示模式或 `packaging-comparison` 横屏比较模式；后者读取专用参考，并把每种真实成片样板登记为独立证据源。
3. 判断画幅并写入项目级版式合同。横屏运行 `python -X utf8 "<本 Skill 目录>/scripts/fixed_layout_contract.py" init "<工程目录>" --mode landscape`；竖屏运行同一命令并使用 `--mode vertical`。同时运行 `python -X utf8 "<本 Skill 目录>/scripts/validate_first_pass_gate.py" init "<工程目录>" --workflow evidence-demo --source-video "<源视频>" --layout-mode <landscape|vertical>`；返修时增加 `--baseline-version "<最近一次完整已确认版本>"`。横竖屏测试必须新建版本，不覆盖旧版。
4. 抽取逐词口播时间轴，专项听校否定词、专有名词和数字，建立语义场景和证据映射。
5. 清洗所有辅助录屏，记录安全时间段；先准备独立稳定镜头，再设计必要的点击、滚动和标注。
6. 建立固定人物小窗、固定单行字幕和模式对应的主画面结构，并写入冻结表。
7. 按首版一致性闸门生成代表性样片包：封面→正文边界、第一次真实证据、每种场景模板、每个关卡→案例边界、结尾和最后一帧；在 `first_pass_gate.json` 登记真实检查产物。
8. 同时运行版式合同校验和 `python -X utf8 "<本 Skill 目录>/scripts/validate_first_pass_gate.py" validate "<工程目录>" --workflow evidence-demo`；两个闸门全部通过后，才渲染完整预览。
9. 从最终 MP4 做全时间轴抽帧、动态段连续播放、音频与中间资产时长复查，通过后导出高质量发布版。

## 工程和真源

- 工程、原始素材和最终成片目录由当前用户提供或在当前工作区建立；Skill 不假定盘符、用户名或共享目录。
- 版本使用 `v01/v02` 或 `build01/build02` 递增，不覆盖旧工程。
- 口播、字幕、页面动作和故事板必须由同一份语义时间轴驱动。
- 本 Skill 的工程目录覆盖 `video-use` 的默认 `<videos_dir>/edit/` 目录；`video-use` 只提供技术方法。
- 未授权剪辑时使用连续源片时间轴，不创建切段 EDL，不应用切点淡化或多段重排。

回归参考只使用发布包内的固定合同、profile 哈希和回归样例。用户点名的新对标可以决定素材关系和开头结构，但不得覆盖人物、字幕、黄框、字体、颜色和动效白名单。私人历史工程不是公开 Skill 的运行依赖。
